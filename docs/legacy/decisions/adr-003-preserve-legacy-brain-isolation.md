# Preserve legacy brain isolation

> **Document control:** ADR-003 · Superseded on this branch by [ADR-004](../../decisions/adr-004-retire-the-legacy-brain-on-this-branch.md) (2026-10-20); the text below is the original decision and is kept as history · Custodian: Repository maintainer

**Decision source:** User-fixed design decisions recorded in ARC-004, section
2, on 2026-10-11. This record transcribes that decision; it is not a new
approval.

## Context

The universal-game work adds a new shared agent path while an existing
Minecraft brain and its operational state remain in use. Reusing or silently
migrating that state could change the established system and make results
difficult to attribute.

## Decision

Keep the legacy Minecraft brain isolated and unchanged by the universal-game
path. The universal path starts fresh and has separate state. The source
architecture is [ARC-004](../../architecture/arc-004-universal-games.md).

## Consequences and limits

Storage paths, checkpoints, and deployment configuration must preserve the
separation. This is a design constraint, not evidence that every deployment
has been audited for isolation. Current implementation and validation status
are tracked in ARC-004 and the
[claims register](../../governance/gov-005-claims-evidence-register.md).

## Alternatives recorded in the source design

Migrating or sharing the legacy brain state was rejected to avoid altering the
working deployment and confounding evaluation of the new path.
