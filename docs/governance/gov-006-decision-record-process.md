# Decision record process

> **Document control:** GOV-006 · Active reference · Custodian: Repository maintainer

## Purpose and scope

This document defines how durable architecture and governance decisions are
recorded. Decision records preserve the context and consequences of a choice;
they do not replace implementation documentation, experiment protocols, or
evidence records.

Individual records live in `docs/decisions/` and use the permanent `ADR-NNN`
identifier and `adr-NNN-short-description.md` filename. See the [documentation
index](../README.md#decisions) for the register.

## Required record fields

Each record states its status, date or source of decision, context, decision,
alternatives considered when recorded, consequences, and links to the affected
architecture and implementation. A decision transcribed from an existing
approved design must say so; its record date must not be presented as a new
approval date.

Statuses are **Proposed**, **Accepted**, **Superseded**, or **Withdrawn**.
Accepted records remain historical even when superseded. Create a new record
that links back to the earlier one; never recycle an identifier or rewrite the
old decision to imply it was never made.

Use a decision record for a durable choice with material consequences across
components or future work. Do not use it to record a measured result, freeze an
experimental procedure, or describe routine implementation details. Use the
[A/B protocol](../foundation/fnd-001-ab-protocol.md) for preregistration and
the [claims and evidence register](gov-005-claims-evidence-register.md) for
the current limits of research claims.

## Maintenance

When a decision changes, add a superseding record and update the index and
affected documents in the same change. Review records when linked code or
configuration changes. A decision record is evidence of repository intent, not
proof that the implementation conforms.
