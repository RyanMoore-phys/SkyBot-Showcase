# Execution record: block implementation plan (GOV-009)

> **Document control:** [GOV-011](../README.md#governance) · Governance / execution record · **State:** In progress · **Custodian:** Repository maintainer · Revision history: Git.

**Date opened:** 2026-10-21. **Executes:** [GOV-009](gov-009-implementation-plan.md). **Branch:** `Adjustments`.
This record documents, package by package, the build of the block implementation plan. It is written as the
work proceeds. **The original build entries were untested; later validation is recorded
separately in section 7.** A package marked "Built, untested" has code
written behind a switch that is off by default; it has not been run, reviewed against
behaviour or A/B tested, and it is not promoted.

## 1. Purpose

To keep an honest, ordered account of what was built, how it differs from the plan, and what
must be verified before any claim is made. Statuses and evidence follow
[GOV-008](gov-008-human-like-learning-motivation.md) and [ASS-007](../assurance/ass-007-adaptability-evaluation-protocol.md).

## 2. Execution rules (build-only mode)

Owner instruction, 2026-10-21: follow the plan strictly; **do not run tests and do not
scan code**; tests come later; document any change that departs from the plan; for a large
out-of-scope change, **update the documents first, revise the plan, then implement**;
limit token usage; no tests means no A/B and no promotion.

| # | Rule |
|---|---|
| E1 | **Strict plan order.** Packages are built in the order of the plan (GOV-009 section 5; GOV-010 section 5). One package at a time. |
| E2 | **Build-only.** No unit, contract or mock run, no A/B (gates P5, P6, P7 are deferred, not skipped: they are listed per package as "tests to write and run later"). No package is promoted; P8 is not reached. |
| E3 | **Package states:** *Not started*; *Built, untested* (code written behind a switch, nothing run); *Deferred* (with the reason and what unblocks it). Nothing is "done" until tests and the A/B have run. |
| E4 | **Verify before edit (P3), narrowly.** Read only the files and regions that will be edited, plus targeted reference checks for a symbol being changed or removed. No broad scanning of the repository. A syntax-only compile check (`python -m py_compile`) of touched files is permitted because it is not a test; the documentation check (`tools/check_docs.py`) is permitted at the end of each phase. |
| E5 | **Default OFF.** Every new behaviour is behind a config switch, off by default and off reproducing the previous behaviour. New logic goes in new modules where possible, imported lazily, so the existing system is unchanged while switches are off. Edits to existing files are minimal and guarded. |
| E6 | **Universal and learned, not declared.** No game-name checks in learning code. No fixed game or task meaning. Each entry records the five-question learned-versus-declared review (GOV-009 17.3). |
| E7 | **Research designs (P1) and protocols (P2) are deferred** to the test phase. Each execution entry carries what P1 requires in brief: switch names, minimal wiring set, kill criteria. A separate record is written when the package is tested. |
| E8 | **Deviations.** Anything done differently from the plan is written in the deviation table **at the time it is made**. A change that is large or out of scope is not made until the plan is revised in the documents. |
| E9 | **Deferred items stay deferred.** R0 (audit of not-established lines) is done only where building a relation requires reading its endpoint code. WP-15b (removing Minecraft-only learning terms) needs a measurement of each term's income in Doom runs and is deferred. Hard items in RES-007 and RES-009 are not built. |
| E10 | **When unsure whether something is Minecraft-only, keep it** and list it in the entry's "pending review" list. Deletions are limited to what the plan classes as legacy path or interface-neutral and that can be shown unreferenced by a targeted check. |
| E11 | No commit, no deployment, no host runs. |

## 3. Entry template

Each package appends one entry: **Package and plan reference; State; Files created or
changed; Switches (key, default); What was implemented against the plan; Deviations;
Verify-before-edit notes (what was read); Learned-versus-declared review (five answers);
Minimal wiring set (RES-008 line ids); Kill criteria; Tests to write and run later; A/B to
run later; Risks and things to verify.**
